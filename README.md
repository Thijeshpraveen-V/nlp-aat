# Resume NER: Pretrained vs Fine-Tuned BERT

NLP for LLM AAT (24AM7PCLLM). Resume parsing with Named Entity Recognition, measuring how much
fine-tuning `dslim/bert-base-NER` on resumes improves over using it as-is.

| Condition | What it is |
|---|---|
| **Before** | `dslim/bert-base-NER` (CoNLL-2003: PER/ORG/LOC/MISC) used as-is, labels mapped PER→NAME, ORG→COMPANIES_WORKED_AT, LOC→LOCATION |
| **After** | Same checkpoint, new 21-label head, fine-tuned on DataTurks resumes, evaluated on the same test split with the same metric |

Metric: entity-level precision/recall/F1 with `seqeval` (strict, IOB2), micro and macro averages.
Results live in `results/` (JSON + `tables/*.md` + `figures/`), all generated by the scripts below.

## Setup

```bash
uv venv --python 3.12 .venv            # or: python -m venv .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
# CUDA build of PyTorch for local GPU training (pick the index matching your driver):
uv pip install --python .venv/Scripts/python.exe --reinstall-package torch torch --index-url https://download.pytorch.org/whl/cu130
```

Kaggle access: put `KAGGLE_API_TOKEN=...` in `.env` (not committed).

## Reproduce

Everything in one go: `bash scripts/run_all.sh`. Step by step:

```bash
PY=.venv/Scripts/python.exe
set -a; . ./.env; set +a
$PY -m kaggle datasets download -d dataturks/resume-entities-for-ner -p data/raw --unzip
$PY src/log_env.py                 # results/environment.txt
$PY src/data_prep.py               # Phase 1: span→BIO, splits, stats, label_distribution.png
$PY src/pretrained_eval.py         # Phase 2A: BEFORE numbers  → results/metrics_pretrained.json
# Phase 2B: grid, select by validation F1, final model
$PY src/finetune.py --tag hp_lr3e-5_bs8 --lr 3e-5 --batch_size 8 --epochs 10   # (repeat for the grid)
$PY src/select_config.py
$PY src/finetune.py --tag main <selected args> --save_model                     # → models/main
# Phase 3 ablations + 5-fold CV
$PY src/finetune.py --tag abl_cw <args> --class_weights
$PY src/finetune.py --tag abl_os <args> --oversample
$PY src/finetune.py --tag abl_trunc <args> --truncate
$PY src/finetune.py --tag abl_raw <args> --variant raw
$PY src/finetune.py --tag cv_main <args> --cv
# Phases 4-5
$PY src/benchmark.py && $PY src/evaluate.py && $PY src/error_analysis.py
```

GPU training on Colab: `notebooks/train_colab.ipynb` runs the same scripts.

## Report and slides

Both are generated from the results files (no hand-typed numbers):

```bash
$PY src/report_figures.py                 # architecture / workflow diagrams
$PY src/data_quality.py                   # annotation-quality statistics used in the report
cd report && npm install && node build_report.js && cd ..             # -> report/report.docx
powershell -ExecutionPolicy Bypass -File report/export_pdf.ps1        # Word: update TOC, -> report/report.pdf
$PY slides/build_slides.py                # -> slides/AAT_presentation.pptx (from LLM AAT_template.pptx)
```

`export_pdf.ps1` drives Microsoft Word through COM. If it hangs, Word is usually waiting on a hidden
recovery dialog: close all Word windows (or end WINWORD.EXE in Task Manager) and run it again.

## Demo (FastAPI + React)

```bash
cd frontend && npm install && npm run build && cd ..      # once
.venv/Scripts/python.exe -m uvicorn app.api:app --port 8000
# open http://127.0.0.1:8000
```

For frontend development: run the API as above, then `cd frontend && npm run dev` (Vite proxies to :8000).

Deep links (handy for a live demo or screenshots): `/?sample=test_resume_082.txt&mode=compare&view=text`
auto-parses a sample (`mode` = pretrained | finetuned | compare, `view` = text | fields); `/#results` opens the Results tab.

Run the server and `src/benchmark.py` from a normal (foreground) terminal: Windows 11 power throttling
slows background processes to efficiency cores, which inflated CPU latency about 5x in our tests.

The demo has a **Live demo** tab (upload PDF/DOCX/TXT or pick a sample, view pretrained, fine-tuned or
side by side; held-out test samples also show the gold annotation and per-document F1) and a
**Results** tab (before-vs-after table, CV, ablations, figures).

API:

```bash
curl -F file=@data/sample_resumes/sample_fictional.pdf -F model=finetuned http://127.0.0.1:8000/parse
```

returns `{name, email, phone, skills[], education{}, companies[], designations[], entities[{text,label,start,end}], latency_ms}`.
`model=both` returns both models; `POST /parse_text` takes JSON `{"text": ...}`. Interactive docs at `/docs`.

CLI: `python src/parse_resume.py <file> --model finetuned|pretrained`.

## Notes on the data

The DataTurks annotations use inclusive `end` offsets, contain overlapping spans and some offsets
shifted by a few characters. `data_prep.py` trims spans, resolves overlaps (longer span kept),
expands spans to word boundaries and logs every case in `results/data_stats.json`.
